## 1. Executive Summary

Version 3.0.0 introduces **Autonomous Multi-Tier Interactive Task Resolution** and **Strict Completion Guardrails**, transforming how conversational pauses and human-in-the-loop prompts from Google Jules Cloud VMs are handled:

1. **Strict Completion & Merging Guardrail:**
   - Sessions in `Awaiting User Feedback` / interactive state are **never considered completed**.
   - `scripts/jules_poll_wait.sh` halts and exits with **code 10** (`INTERACTIVE_STATE`).
   - `bin/jules-gate merge` strictly blocks review branch merges with **exit code 5** if a task is in interactive state.
   - Review branches are only verified and merged once Jules concludes with a true terminal success state (`Completed`).
2. **Direct Google AIDA REST API Engine (`scripts/jules_api.py`):**
   - Live question extraction from activity stream: `GET https://aida.googleapis.com/v1/swebot/tasks/{id}/activities` (`requiresUserResponse: true`).
   - In-VM feedback dispatch: `POST https://aida.googleapis.com/v1/swebot/tasks/{id}:interact` delivers `feedbackGiven.feedback` directly into the running VM without losing in-memory state.
3. **3-Tier Escalation Hierarchy:**
   - **Tier 1 (Sub-Agent Autonomous Clarification):** Sub-agent evaluates question against original task contract. If answers exist in contract specifications, answers via `jules-gate interact <id> "<answer>"` and resumes zero-token wait.
   - **Tier 2 (Main Calling Agent Escalation):** If underspecified in contract, sub-agent messages Main Calling Agent (`send_message`).
   - **Tier 3 (Human Developer Escalation):** Main Calling Agent prompts developer via `ask_question` modal before cascading the response down to the Cloud VM.
